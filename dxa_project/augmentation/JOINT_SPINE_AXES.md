# Совместная непрерывная ось позвоночника: алгоритм для пайплайна хакатона

Версия `joint_continuous_contour_l1`. Реализация: `joint_spine_axes.py`.
Единый входной метод `analyze_spine` используется генератором аугментаций
и геометрическим инференсом. Модели предсказывают разделительные линии;
контуры и этот совместный подбор выполняются затем на исходных пикселях.

## Формулировка

Пусть `D₀…Dₖ` — упорядоченные разделительные прямые. Для верхнего частично
видимого позвонка добавляется верхняя граница кадра. На каждой прямой
выбираем **одну** точку `Qᵢ`, общую для двух соседних осей.
Ось позвонка `i` — отрезок `[Qᵢ,Qᵢ₊₁]`. Таким образом, конец верхней оси
и начало нижней совпадают точно, а не только с некоторым допуском.

Контуры сначала дают геометрические середины поперечных сечений `Mᵢⱼ`.
Для каждого сечения фиксируем долю высоты `fᵢⱼ` между двумя прямыми
в направлении исходного перпендикуляра. Предсказанная точка оси:

`Pᵢⱼ = (1−fᵢⱼ) Qᵢ + fᵢⱼ Qᵢ₊₁`.

Совместно минимизируем:

`Σᵢ (1/Nᵢ) Σⱼ [ |vᵢ·(Mᵢⱼ−Pᵢⱼ)| + |uᵢ·(Mᵢⱼ−Pᵢⱼ)| ]`.

Здесь `vᵢ` — поперечное направление из трапеции, `uᵢ` — перпендикуляр вниз.
Используются центральные 70% сечений; каждому позвонку даётся одинаковый
суммарный вес. Все расстояния считаются в миллиметрах.

Это максимум правдоподобия **при принятой модели ошибок Лапласа**
в фиксированных локальных координатах. Это рабочая модель ошибок контура,
а не вероятность анатомической правильности. Параметр масштаба ошибок
считается общим, поэтому для поиска оптимума его можно опустить.

## Жёсткие ограничения

* `Qᵢ` лежит на соответствующей разделительной прямой.
* Общая точка находится в пересечении допустимых интервалов контуров соседей.
* Для `Δᵢ = Qᵢ₊₁−Qᵢ`: `uᵢ·Δᵢ > 0` и
  `|vᵢ·Δᵢ| ≤ tan(12°) (uᵢ·Δᵢ)`.
* Отдельные отрезки могут иметь разные наклоны: дополнительное выпрямление
  или штраф за сколиоз не вводится.

## Алгоритм

1. Построить контуры от центрального позвонка к краям по
   [VERTEBRAL_CONTOURS.md](VERTEBRAL_CONTOURS.md). Сохранить боковые границы,
   их середины и локальные направления. Независимые оси нужны только
   как диагностический промежуточный результат.
2. Параметризовать каждую точку `Qᵢ = Oᵢ + λᵢ dᵢ` вдоль своей прямой.
   Найти границы `λᵢ` по общему интервалу соседних контуров.
3. Составить одну задачу линейного программирования для всех `λᵢ`.
   Модули ошибок представить неотрицательными вспомогательными переменными;
   угловые ограничения также линейны.
4. Решить задачу HiGHS. При фиксированных контурах и долях высоты получается
   глобальный минимум сформулированной выпуклой задачи. Это не совместная
   оптимизация самой сегментации и осей.
5. Записать одну общую цепочку точек; соседние оси используют буквально
   одинаковые координаты. Верхний фрагмент участвует в той же задаче,
   если его контур пригоден.
6. Пересчитать углы, длины, ошибки на центральных 70% сечений, средний
   межлинейный шаг, долю верхнего фрагмента и глобальную ось.
7. Проверить непрерывность, предел 12°, высокие ошибки и выход за контур.
   Если контуры отсутствуют, интервалы не пересекаются или ограничения
   несовместимы, совместная ось не определяется. Не заменять результат
   несогласованными независимыми осями для вычисления таргетов.

## Визуализация и последующее использование

Галерея `outputs/spine_axes_50_joint_final/index.html`: зелёные разделители,
синие контуры, оранжевые геометрические середины, жёлтые отрезки осей,
розовые общие узлы. Подробные JSON сохраняют стоимость совместной задачи,
координаты узлов и независимые промежуточные оси.

Проверки укладки, наклона и геометрических углов используют **совместные**
оси. До и после будущей аугментации вызывается один и тот же метод.
Предел 12° относится к локальному перпендикуляру и не меняет диапазоны
аугментационного поворота всей картинки. Обучение и реальная аугментация
при внедрении этого алгоритма не запускаются.
