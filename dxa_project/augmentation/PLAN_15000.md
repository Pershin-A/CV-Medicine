# План набора аугментаций

## Папка и происхождение

Готовый набор записан в `dxa_project/outputs/augmented_15000_final/`; все квоты ниже выполнены. `augmented_15000/` содержит незавершённый промежуточный запуск и не используется для обучения.

```text
augmented_15000/
  images/SPINE/*.dcm
  images/LEG_LEFT/*.dcm
  images/LEG_RIGHT/*.dcm
  geometry/*.json
  manifest.csv
  generation_report.json
```

Каждому DICOM соответствует JSON; геометрия и таргеты также записываются в private DICOM-теги. Манифест содержит исходный путь, Study UID, преобразование, масштаб пикселя, его происхождение, удалённые объекты и пересчитанные таргеты. Непустую выходную папку генератор не перезаписывает. Оригиналы сохраняются. Все 15 000 файлов проверены, подробности в audit_report.json.

| Область | Позитивы по двум условиям | Негативы укладки/позиционирования | Негативы оси/ROI | Всего |
|---|---:|---:|---:|---:|
| Позвоночник | 2500 | 1250 | 1250 | 5000 |
| Левое бедро | 2500 | 1250 | 1250 | 5000 |
| Правое бедро | 2500 | 1250 | 1250 | 5000 |

Группы описывают стратегию генерации. Нарушения могут пересекаться: фактическая частота каждого таргета подсчитывается отдельно. При невозможности заполнить квоту отчёт показывает недобор, а не принимает неподходящие изображения. Train/validation делятся по исходному исследованию до аугментации; производные одного исследования всегда остаются в одной части.

## Последовательность проверок

Финальные оси позвоночника вычисляются одним совместным подбором
с общей точкой соседей: [JOINT_SPINE_AXES.md](JOINT_SPINE_AXES.md).
Все последующие углы и условия укладки используют эту непрерывную цепочку.
Крайние оси затем уточняются по высотам, а верхний контур перестраивается симметрично: [TERMINAL_AXIS_REFINEMENT.md](TERMINAL_AXIS_REFINEMENT.md).

1. Прочитать актуальную `Размеченные/labels.csv`, JSON и манифест; проверить флаг завершения, размеры и геометрию. Отсутствие невидимой структуры допустимо, но такой источник может не подходить для получения позитивов.
2. Продлить межпозвоночные прямые до боковых границ. ROI левого бедра продлить влево, правого — вправо. Исходные JSON не изменяются.
3. Для позвоночника построить контуры и оси в физических координатах методом из [VERTEBRAL_CONTOURS.md](VERTEBRAL_CONTOURS.md). Начать с центрального позвонка и двигаться к краям. Яркостная сегментация выбирает связный кластер, закрывает мелкие разрывы и внутренние отверстия. На 41 поперечном уровне находятся боковые границы, затем **геометрическая середина между ними**. В центральных 70% высоты ось приближает середины по сумме абсолютных отклонений; отклонение от исходного перпендикуляра ограничено ±12°. ROI визуализируется контуром, а не bounding box. Соседи согласуются на общей разделительной прямой и по горизонтальному перекрытию bbox. Верхний фрагмент ограничен кадром и первой разделительной линией.
4. Компенсировать исходный наклон позвоночника и задавать целевой угол: позитив `[-4,4]`, негатив `[-10,-6] ∪ [6,10]`. С вероятностью 0,5 отражать относительно вертикали; точки L/R менять местами относительно снимка. Поворот выполняется с учётом разных размеров пикселя по X/Y. Преобразование вычисляется одной матрицей, чтобы не интерполировать дважды.
5. Проверять покрытие выходного изображения исходными пикселями. Zoom сохраняет размер массива. Для укладки требуются 4–7 линий, обе видимые верхние точки костей и отношение верхнего фрагмента к среднему расстоянию вдоль осей между соседними линиями от 0,25 до 0,75. Отступ костей от края не требуется. Недостоверная ось означает неопределённость, а не автоматически норму.
6. Для бедра одновременно проверить три точки с отступом 2,5% меньшей стороны и ROI: ≥30 мм сверху/снизу, ≥20 мм латерально. Проверка точек эквивалентна проверке содержащего их прямоугольника внутри безопасной рамки. Позитивные центры zoom выбираются из допустимых интервалов; негативы ROI намеренно нарушают один зазор.
7. Точки вне кадра удалить, остальные объекты обрезать по рамке. Применять пороги видимой доли для линий/рамок; маска вертела сохраняет все оставшиеся пиксели. Ротация переносится только для полностью видимой ненулевой маски; иначе 1. При нулевой маске показывать оставшийся красный пунктир контура. Артефакты отдельно не синтезировать; исчезновение всех размеченных рамок меняет их таргет на 0, при неизвестной полноте разметки — неопределённость.
8. На полученных пикселях повторно вычислить оси, укладку, позиционирование, ROI и прочие изменяемые таргеты. Принимать только соответствующую группе комбинацию и фактически измеренный угол из заданных диапазонов.
9. Записать DICOM, JSON и строку манифеста. Проверить соответствие размеров и метаданных. В итоговом отчёте сохранить причины отказов и фактическое покрытие таргетов.

## Ограничения

В исходных DICOM нет подтверждённого индивидуального масштаба. Используется сообщённый номинал Y=1,05 мм, X=0,6 мм; после zoom шаг делится на масштаб. Реальные DICOM spacing-теги при наличии имеют приоритет. Номинал не доказывает калибровку ранее увеличенных изображений. Контуры и оси пока не имеют отдельной эталонной разметки: синтетические тесты проверяют алгоритм, а галерея 50 снимков позволяет проверить его анатомический смысл вручную. Сложные наложения и недостаточная видимость помечаются для просмотра.

Проверка без полной генерации:

```powershell
.\.venv\Scripts\python.exe -m pytest dxa_project/tests/test_vertebral_axes.py dxa_project/tests/test_augmentation.py -q
```

Будущий запуск после просмотра галереи:

```powershell
.\.venv\Scripts\python.exe -m dxa_project.augmentation.generate --output dxa_project/outputs/augmented_15000
```
