# Геометрические аугментации DXA

## Структура набора

После запуска создаётся новая папка `dxa_project/outputs/augmented_dataset/`:

```text
augmented_dataset/
  images/
    SPINE/*.dcm
    LEG_LEFT/*.dcm
    LEG_RIGHT/*.dcm
  geometry/*.json
  manifest.csv
  generation_report.json
```

Каждому DICOM соответствует один JSON с разметкой в исходной схеме `labeler/geometry.py`. `manifest.csv` хранит путь к оригиналу, исходный Study UID для группового разделения train/validation, преобразование, фактически пересчитанные метки и число удалённых объектов. Имена файлов не содержат сведения о пациенте. Оригиналы и исходные таблицы не меняются. Запись в непустую выходную папку запрещена.

## Источники и объём

Используются `dxa_project/outputs/manifest.csv` и `Размеченные*/labels.csv` с JSON из `geometry_path`. Изображение допускается только при `complete.spine=true` или `complete.hip=true`, валидной геометрии и исходно корректной проверке, которую собираемся нарушать. Если подходящих оригиналов нет, генератор не выдумывает разметку и сообщает недобор.

План на каждую область: 500 изображений, положительных по обеим проверкам; 250 с нарушением укладки/позиционирования; 250 с нарушением оси/ROI. Обе метки пересчитываются для **каждого** результата. Поэтому в двух отрицательных группах возможны пересечения нарушений; `generation_group` обозначает цель создания, а столбцы меток — фактическое состояние.

## Правила

* Все преобразования — изотропный zoom, при необходимости с поворотом; размер массива не меняется. Каждый выходной пиксель обязан происходить из исходного изображения. Варианты с неизвестной областью за рамкой исходного снимка отбрасываются.
* Укладка позвоночника: 5 или 6 видимых линий; расстояние от верхней рамки до первой линии составляет 0,25–0,75 медианного межлинейного шага; обе верхние точки подвздошных костей находятся внутри с отступом 2,5% меньшей стороны. Это **операционное приближение** к правилу «видна половина Th12», поскольку отдельного контура Th12 в текущей схеме нет. Сценарии: слишком сильное отсечение Th12; Th12 и следующего позвонка; левой/правой подвздошной кости; обеих костей снизу.
* Ось позвоночника: между каждой парой разделительных линий на трёх уровнях ищется центр симметрии яркости, по центрам строится ось позвонка. Глобальная ось соединяет верхний конец верхнего позвонка и нижний конец нижнего. Угол измеряется от вертикали. Измеренный исходный угол компенсируется поворотом, затем задаётся целевой угол из `[-20,-6]`, `[-4,4]` или `[6,20]`; метка определяется **повторно измеренным** углом: `abs(angle)>5°` — нарушение. Целевые диапазоны учитывают ошибку оценки.
* Позиционирование бедра: все три опорные точки должны быть внутри с отступом 2,5% меньшей стороны; иначе нарушение.
* ROI бедра: прямоугольник должен целиком остаться видимым; отступы сверху и снизу не менее 30 мм, латерально не менее 20 мм. Для `LEG_LEFT` латеральная сторона — правая рамка, для `LEG_RIGHT` — левая. Сторону необходимо сверить с фактической ориентацией экспортируемых снимков перед обучением.
* `PixelSpacing` в текущих 499 DICOM отсутствует. По умолчанию запасной режим оценивает масштаб по **предположению**, что исходный размеченный ROI соответствует требуемым отступам, с запасом 10%. Метки помечаются `spacing_basis=roi_proxy` и **не являются подтверждёнными сантиметровыми измерениями**. `--no-roi-proxy` требует реального DICOM масштаба и оставляет эти источники вне набора.
* Линия удаляется, если видимо менее половины длины; рамка или полигон — если видимо менее половины площади; вышедшая точка удаляется. Частично видимая линия/рамка обрезается по границе. Артефакты тоже преобразуются; если прежний положительный класс артефакта исчез и полнота его разметки неизвестна, класс становится пустым, а не автоматически отрицательным. Ротация бедра не синтезируется; её метка оставляется пустой на новых изображениях.

## Проверка и будущий запуск

Пока разметка не завершена, запускать генерацию на реальных данных не следует. Выполнены только синтетические тесты:

```powershell
.\.venv\Scripts\python.exe -m pytest dxa_project/tests/test_augmentation.py -q --basetemp dxa_project/tests/.tmp_synth_20260926
```

После завершения разметки из корня хакатона:

```powershell
.\.venv\Scripts\python.exe -m dxa_project.augmentation.generate
```

При нехватке подходящих источников или невозможности получить заданный сценарий `generation_report.json` показывает фактические количества и причины отказов. Новые изображения необходимо разделять на train/validation по `source_study_uid`, совместно с оригиналами того же исследования.
