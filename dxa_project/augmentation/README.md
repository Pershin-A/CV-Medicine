# Геометрические аугментации DXA

Для финальных осей используется [совместный непрерывный подбор](JOINT_SPINE_AXES.md).
Новая галерея 50 примеров: `outputs/spine_axes_50_terminal_final/index.html`.
Крайние оси и верхний симметричный контур: [TERMINAL_AXIS_REFINEMENT.md](TERMINAL_AXIS_REFINEMENT.md).

## Структура набора

Актуальный подробный план: [PLAN_15000.md](PLAN_15000.md). Полная генерация завершена: 15 000 изображений в `outputs/augmented_15000_final`, автоматический аудит без ошибок. Отчёт обучения: `outputs/geometry_ml_augmented_5epochs/REPORT.md`.

После запуска создаётся новая папка `dxa_project/outputs/augmented_15000/`:

```text
augmented_15000/
  images/
    SPINE/*.dcm
    LEG_LEFT/*.dcm
    LEG_RIGHT/*.dcm
  geometry/*.json
  manifest.csv
  generation_report.json
```

Каждому DICOM соответствует один JSON с разметкой в исходной схеме `labeler/geometry.py`. `manifest.csv` хранит путь к оригиналу, исходный Study UID для группового разделения train/validation, преобразование, фактически пересчитанные метки и число удалённых объектов. Имена файлов не содержат сведения о пациенте. Оригиналы и исходные таблицы не меняются. Запись в непустую выходную папку запрещена.

В производный DICOM также записываются **его собственная** преобразованная
геометрия (частный тег DXA_MANUAL_LABELER 0x09) и пересчитанные таргеты
(частный тег 0x0A). Таким образом, копия прежней геометрии исходного DICOM
не остаётся источником ошибочной разметки. Номинальный физический масштаб
остаётся в manifest, а не в стандартном PixelSpacing, поскольку фактическая
калибровка в исходниках не подтверждена.

## Источники и объём

Используются `dxa_project/outputs/manifest.csv` и **только** `Размеченные/labels.csv` с JSON из `geometry_path`. Путь к папке разметки можно задать через `--annotations-root`. Изображение допускается только при `complete.spine=true` или `complete.hip=true`, валидной геометрии и исходно корректных проверках. Если подходящих оригиналов нет, генератор не выдумывает разметку и сообщает недобор. Отсутствие структур и соответствующих точек у снимков 75, 79 и 81 является содержательной разметкой; они отмечены завершёнными, но не используются как положительные источники для аугментации позиционирования.

План на каждую область: 2500 изображений, положительных по обеим проверкам; 1250 с нарушением укладки/позиционирования; 1250 с нарушением оси/ROI. Всего около 15000. Обе метки пересчитываются для **каждого** результата. Поэтому в двух отрицательных группах возможны пересечения нарушений; `generation_group` обозначает цель создания, а столбцы меток — фактическое состояние.

## Правила

* Все преобразования — изотропный zoom, при необходимости с поворотом; размер массива не меняется. Каждый выходной пиксель обязан происходить из исходного изображения. Варианты с неизвестной областью за рамкой исходного снимка отбрасываются.
* Линии разделения продлеваются до боковых границ. Укладка: 4–7 линий; длина верхнего фрагмента вдоль найденной оси составляет 0,25–0,75 **средней** длины осей между соседними линиями; обе верхние точки костей внутри кадра, без дополнительного отступа. Для негативов используются отсечение Th12/следующего позвонка или одной/обеих костей. При неуверенной яркостной оценке результат проверки неопределён.
* Оси и контуры: метод описан в [VERTEBRAL_CONTOURS.md](VERTEBRAL_CONTOURS.md). Вместо прямоугольного ROI выделяется связный кластер тела; центр сечения — середина между боковыми границами, без весов яркости. Обработка идёт от центрального позвонка к краям, с проверкой перекрытия соседей. L1-прямая ограничена ±12° относительно исходного перпендикуляра. Контур и оси повторно вычисляются после преобразования. Целевые углы всей аугментации: позитивы [-4,4], негативы [-10,-6] ∪ [6,10]; отражение относительно вертикали сохраняется.
* Позиционирование бедра: все три опорные точки должны быть внутри с отступом 2,5% меньшей стороны; иначе нарушение.
* ROI бедра перед преобразованием продлевается по произвольной стороне до границы кадра: у `LEG_LEFT` левая сторона становится `x=0`, у `LEG_RIGHT` правая — `x=width−1`. Исходный JSON не меняется. Для проверки используются три осмысленные стороны ROI: верхняя, нижняя и латеральная. Для `LEG_LEFT` латеральная сторона ROI — правая, для `LEG_RIGHT` — левая. Отступы сверху и снизу должны быть не менее 30 мм, латерально — не менее 20 мм. Все три опорные точки должны попадать в ROI в исходной разметке, когда все структуры присутствуют.
* Для малого вертела сохраняются оба исходных контура и отдельное поле `hip.lesser_trochanter_pixels`. Строки, где размечен вертел, задают участок линии кости. Отрезок между его крайними точками задаёт продольную ось; оба реальных контура пересекаются с перпендикулярными сечениями этой оси. Знаковый зазор определяется направлением к кости с вертикальной компонентой вверх. Профиль зазора сглаживается медианным фильтром ширины 5 и гауссовым фильтром σ=1,5. От максимума ищутся минимумы слева и справа; если плечо не размечено, границей служит конец контура. Закрашиваются только сечения с положительным зазором более 0,5 пикселя (допуск на неточность карандаша). Заливка лежит между **реальными** контурами, не между выпрямленными линиями. При отсутствии положительного зазора площадь равна нулю: показывается **красный пунктирный контур малого вертела**. Исходные линии остаются в JSON.
* При zoom пиксельная маска и оба контура обрезаются независимо. Если часть ненулевой маски вышла за кадр, остаток остаётся красным, поле `hip.lesser_trochanter_partial=true`, а метка ротации становится `1`. При нулевой площади метка тоже `1`; лишь для целиком видимой ненулевой маски исходная метка ротации переносится. Даже короткий оставшийся фрагмент пунктирного контура сохраняется в JSON.
* В исходных 499 и размеченных 499 DICOM не найдено тегов физического размера пикселя. По умолчанию используются указанные пользователем **номинальные** размеры сканера: 1,05 мм/пиксель по Y и 0,6 мм/пиксель по X; после zoom они делятся на коэффициент масштаба. Если DICOM содержит физический масштаб, он имеет приоритет. В `manifest.csv` записываются `spacing_basis`, оба размера пикселя и зазоры ROI в сантиметрах. Порог ROI: сверху и снизу ≥3 см, с латеральной стороны ≥2 см. Положительные ROI выбираются с запасом 0,5 мм; отрицательные специально ставятся ниже одного из порогов при сохранении остальных условий. Так как часть исходных изображений могла быть предварительно увеличена, номинальный масштаб может отличаться от эффективного: сантиметровые метки требуют сверки с независимой калибровкой. `--require-dicom-spacing` пропускает бедра без DICOM масштаба.
* Межпозвоночная линия удаляется, если видимо менее половины её нормализованной длины; рамка артефакта или полигон — если видимо менее половины площади; вышедшая точка удаляется. Частично видимая линия/рамка обрезается по границе. Артефакты тоже преобразуются; если прежний положительный класс артефакта исчез и полнота его разметки неизвестна, класс становится пустым, а не автоматически отрицательным. Пиксели и контуры малого вертела обрезаются по кадру без порога видимой доли для маски; видимые фрагменты контуров сохраняются.

## Проверка и будущий запуск

Проверка исполняемости:

```powershell
.\.venv\Scripts\python.exe -m pytest dxa_project/tests/test_augmentation.py labeler/tests/test_complete_annotations.py -q
```

Запуск из корня хакатона:

```powershell
.\.venv\Scripts\python.exe -m dxa_project.augmentation.generate
```

При нехватке подходящих источников или невозможности получить заданный сценарий `generation_report.json` показывает фактические количества и причины отказов. Новые изображения необходимо разделять на train/validation по `source_study_uid`, совместно с оригиналами того же исследования.

Пробный запуск на реальных данных создаёт 30 исходных примеров (по 10 на область) и по 5 аугментаций каждого. Готовый набор находится в `dxa_project/outputs/pilot_30/`: `index.html` открывает 30 листов 2×6, `manifest.csv` содержит метки для всех 180 столбцов, `report.json` — покрытие таргетов. Все 150 новых DICOM и соответствующие JSON находятся в подпапках `images/` и `geometry/`. Листы также содержат визуальную разметку исходных снимков. В каждой области выбраны и источники с реальными нарушениями, и источники с нормой для артефактов/ротации. Для ротации в аугментации применяется правило площади маски выше. Исходные файлы `Размеченные/` не изменяются: поле пикселей материализуется в выходных JSON из исходных штрихов.

Повторить запуск в новую пустую папку:

```powershell
.\.venv\Scripts\python.exe -m dxa_project.augmentation.pilot_30 --output dxa_project/outputs/pilot_30_new
```

Старый пилот показывает прежние правила; актуальная квота 15 000 достигнута в отдельном финальном наборе.

Проверку физического масштаба и расхождений с табличным ROI можно повторить:

```powershell
.\.venv\Scripts\python.exe -m dxa_project.augmentation.audit_spacing
```

Отчёт сохраняется в `dxa_project/outputs/spacing_audit.json`.

Для визуального разбора расхождений ROI:

```powershell
.\.venv\Scripts\python.exe -m dxa_project.augmentation.visualize_roi_mismatches
```

Страница `dxa_project/outputs/roi_mismatch_review/index.html` показывает
каждый из 24 исходных снимков с ROI, пороговыми линиями и обеими метками.

Все 499 исходных снимков рядом с подготовленной визуальной разметкой:

```powershell
.\.venv\Scripts\python.exe -m dxa_project.augmentation.visualize_original_annotations
```

Галерея находится в `dxa_project/outputs/original_annotations/index.html`.
Фильтры сверху переключают анатомическую область и вид отображения малого
вертела (красная маска или красный пунктир); номера снимков можно ввести через
запятую. Подложка берётся непосредственно из `Исследования/`.

```powershell
.\.venv\Scripts\python.exe -m dxa_project.augmentation.audit_trochanter
.\.venv\Scripts\python.exe -m dxa_project.augmentation.audit_provenance
```

Отчёты сохраняются в `dxa_project/outputs/trochanter_audit.json` и
`dxa_project/outputs/roi_provenance_audit.json`. Второй сравнивает пиксели,
UID, размеры и пути всех 499 исходных и размеченных DICOM. Обновлённый пилот
с новым способом заливки сохранён отдельно в
`dxa_project/outputs/pilot_30_normal_axis/index.html`.

Геометрический загрузчик и модели находятся в `dxa_project/geometry_ml/`, ноутбук — `DXA_geometry_pipeline.ipynb`. Устаревшие прямые классификаторы `train.py` и `train_naive_resnet.py` не используют геометрию. Оси нового метода подключены к генератору, пилоту и геометрическому инференсу. Галерея 50 исходных позвоночников: `outputs/spine_axes_50_contour_midpoints/index.html`; команда создания — `python -m dxa_project.augmentation.visualize_spine_axes`.
