# Геометрические аугментации DXA

## Структура набора

После запуска создаётся новая папка `dxa_project/outputs/augmented_dataset/`:

```text
augmented_dataset/
  images/
    SPINE/*.dcm
    LEG_LEFT/*.dcm
    LEG_RIGHT/*.dcm
  geometry/*.json
  manifest.csv
  generation_report.json
```

Каждому DICOM соответствует один JSON с разметкой в исходной схеме `labeler/geometry.py`. `manifest.csv` хранит путь к оригиналу, исходный Study UID для группового разделения train/validation, преобразование, фактически пересчитанные метки и число удалённых объектов. Имена файлов не содержат сведения о пациенте. Оригиналы и исходные таблицы не меняются. Запись в непустую выходную папку запрещена.

## Источники и объём

Используются `dxa_project/outputs/manifest.csv` и **только** `Размеченные/labels.csv` с JSON из `geometry_path`. Путь к папке разметки можно задать через `--annotations-root`. Изображение допускается только при `complete.spine=true` или `complete.hip=true`, валидной геометрии и исходно корректных проверках. Если подходящих оригиналов нет, генератор не выдумывает разметку и сообщает недобор. Отсутствие структур и соответствующих точек у снимков 75, 79 и 81 является содержательной разметкой; они отмечены завершёнными, но не используются как положительные источники для аугментации позиционирования.

План на каждую область: 500 изображений, положительных по обеим проверкам; 250 с нарушением укладки/позиционирования; 250 с нарушением оси/ROI. Обе метки пересчитываются для **каждого** результата. Поэтому в двух отрицательных группах возможны пересечения нарушений; `generation_group` обозначает цель создания, а столбцы меток — фактическое состояние.

## Правила

* Все преобразования — изотропный zoom, при необходимости с поворотом; размер массива не меняется. Каждый выходной пиксель обязан происходить из исходного изображения. Варианты с неизвестной областью за рамкой исходного снимка отбрасываются.
* Линии разделения позвонков перед преобразованием продлеваются по их наклону вправо и влево до границ изображения. Исходный JSON при этом не меняется. Укладка позвоночника: 4–7 видимых линий; расстояние от верхней рамки до первой линии составляет 0,25–0,75 медианного межлинейного шага; обе верхние точки подвздошных костей находятся внутри с отступом 2,5% меньшей стороны. Отсутствующая метка кости трактуется как отсутствие видимой кости, поэтому укладка не проходит проверку. Критерий для Th12 — **операционное приближение**, поскольку отдельного контура Th12 в текущей схеме нет. Сценарии: слишком сильное отсечение Th12; Th12 и следующего позвонка; левой/правой подвздошной кости; обеих костей снизу.
* Ось позвоночника: между каждой парой разделительных линий на трёх уровнях ищется центр симметрии яркости, по центрам строится ось позвонка. Глобальная ось соединяет верхний конец верхнего позвонка и нижний конец нижнего. Угол измеряется от вертикали. Измеренный исходный угол компенсируется поворотом, затем задаётся целевой угол из `[-20,-6]`, `[-4,4]` или `[6,20]`; метка определяется **повторно измеренным** углом: `abs(angle)>5°` — нарушение. Целевые диапазоны учитывают ошибку оценки.
* Позиционирование бедра: все три опорные точки должны быть внутри с отступом 2,5% меньшей стороны; иначе нарушение.
* ROI бедра перед преобразованием продлевается по произвольной стороне до границы кадра: у `LEG_LEFT` левая сторона становится `x=0`, у `LEG_RIGHT` правая — `x=width−1`. Исходный JSON не меняется. Для проверки используются три осмысленные стороны ROI: верхняя, нижняя и латеральная. Для `LEG_LEFT` латеральная сторона ROI — правая, для `LEG_RIGHT` — левая. Отступы сверху и снизу должны быть не менее 30 мм, латерально — не менее 20 мм. Все три опорные точки должны попадать в ROI в исходной разметке, когда все структуры присутствуют.
* Для малого вертела сохраняются оба слоя свободных штрихов: его контур и контур кости рядом. Вычисляется площадь замкнутой области между кривыми, если обнаружены хотя бы два их пересечения; при отсутствии такой области площадь равна нулю. В `manifest.csv` выводятся площадь в пикселях, число пересечений и доля площади ROI. Порог для ротации бедра пока не калиброван, поэтому её класс у новых изображений остаётся пустым.
* `PixelSpacing` в текущих 499 DICOM отсутствует. По умолчанию запасной режим оценивает масштаб по **предположению**, что исходный размеченный ROI соответствует требуемым отступам, с запасом 10%. Метки помечаются `spacing_basis=roi_proxy` и **не являются подтверждёнными сантиметровыми измерениями**. `--no-roi-proxy` требует реального DICOM масштаба и оставляет эти источники вне набора.
* Линия удаляется, если видимо менее половины её нормализованной длины; рамка артефакта или полигон — если видимо менее половины площади; вышедшая точка удаляется. Частично видимая линия/рамка обрезается по границе. Артефакты тоже преобразуются; если прежний положительный класс артефакта исчез и полнота его разметки неизвестна, класс становится пустым, а не автоматически отрицательным. Ротация бедра не синтезируется.

## Проверка и будущий запуск

Проверка исполняемости:

```powershell
.\.venv\Scripts\python.exe -m pytest dxa_project/tests/test_augmentation.py labeler/tests/test_complete_annotations.py -q
```

Запуск из корня хакатона:

```powershell
.\.venv\Scripts\python.exe -m dxa_project.augmentation.generate
```

При нехватке подходящих источников или невозможности получить заданный сценарий `generation_report.json` показывает фактические количества и причины отказов. Новые изображения необходимо разделять на train/validation по `source_study_uid`, совместно с оригиналами того же исследования.

Пробный запуск на реальных данных создаёт 30 исходных примеров (по 10 на область) и по 5 аугментаций каждого. Готовый набор находится в `dxa_project/outputs/pilot_30/`: `index.html` открывает 30 листов 2×6, `manifest.csv` содержит метки для всех 180 столбцов, `report.json` — покрытие таргетов. Все 150 новых DICOM и соответствующие JSON находятся в подпапках `images/` и `geometry/`. Листы также содержат визуальную разметку исходных снимков. В каждой области выбраны и источники с реальными нарушениями, и источники с нормой для артефактов/ротации. Для ротации в аугментации метка переносится только когда оба её контура целиком остаются в кадре; иначе она неизвестна.

Повторить запуск в новую пустую папку:

```powershell
.\.venv\Scripts\python.exe -m dxa_project.augmentation.pilot_30 --output dxa_project/outputs/pilot_30_new
```

Это проверка исполняемости и наглядности меток, а не проверка достижения полной квоты в 3000 изображений.

Текущие классификаторы в `dxa_project/train.py` и `dxa_project/train_naive_resnet.py` читают только изображения и табличные метки; координаты линий, точек и штрихов в обучение ещё не включены. Поэтому при обучении моделей для анатомических объектов потребуется отдельный загрузчик геометрии или добавление её в существующий конвейер. Значения площади малого вертела пока доступны как признаки в манифесте, без подобранного порога для ротации.
