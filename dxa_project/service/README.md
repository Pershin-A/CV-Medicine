# Итоговый API DXA v2

Гайд запуска, predict с таблицей и двумя папками, четырёхэтапный partial_fit и передача backend-разработчику: [API_GUIDE.md](API_GUIDE.md). Схема: [openapi.json](openapi.json). Описание ниже относится к прежнему queue-based интерфейсу, оставленному для совместимости.

## Прежний queue-based интерфейс

## Запуск

Из папки `C:\Users\Андрей\Desktop\Хакатон`:

```powershell
.venv\Scripts\python.exe -m pip install -r dxa_project\service\requirements.txt
.venv\Scripts\python.exe -m dxa_project.service
```

Swagger с интерактивными запросами: **http://127.0.0.1:8765/docs**.
Запускаются API, CPU-worker аугментации и GPU-worker предсказаний/дообучения.
GPU-worker ждёт завершения текущего эксперимента `retrained_20260929`.
Для работы на CPU: `python -m dxa_project.service --device cpu` тем же Python venv.
Остановка — Ctrl+C; незавершённое задание при следующем запуске отмечается interrupted,
а его зарезервированная очередь освобождается. Готовые этапы и данные сохраняются.

Настройки: `DXA_SERVICE_DATA` (по умолчанию `dxa_project/service_data`),
`DXA_ALLOWED_ROOTS` (дополнительные допустимые папки через `;`), `DXA_CPU_THREADS`
(по умолчанию 2). Указанный клиентом путь относится к серверу. С другого компьютера
используйте `/v1/data/uploads`. DICOM — один кадр, серое изображение.

```json
  "protocol": "C:/Users/Андрей/Desktop/Хакатон/dxa_project/outputs/improvements_v2/protocol.json",
  "activate": true
}
```

После текущего обучения укажите `outputs/retrained_20260929/light` и
`outputs/retrained_20260929/protocol.json`. Не импортируйте ещё записываемые веса.
Импорт копирует пять модулей, калибровку и протокол в отдельную неизменяемую базовую

модулям; по умолчанию router=12, остальные=24. При отличающемся бюджете исходного
эксперимента передайте его явно. Дообучение наследует этот бюджет.

## Предсказания

`POST /v1/model/predict`:

```json
{"paths":["C:/Users/Андрей/Desktop/Хакатон/Исследования/путь/scan.dcm"],"mode":"single"}
```

Для папки: `mode="batch"`. Также доступны `image_ids` ранее загруженных файлов.
Для единичного файла HTTP-запрос ждёт до 10 секунд (`?wait_seconds=30` — до 30).
При свободном worker возвращается JSON результата; иначе HTTP 202 с job_id.
Для немедленного получения job_id используйте `?wait_seconds=0`.
Опрос: `GET /v1/jobs/{job_id}`. Результат: `/v1/results/{result_id}`.

JSON содержит геометрию, флаги 0/1/null, физический масштаб и ссылки на overlay.png,
mask.png и geometry.json. Координаты относятся к исходному снимку. PNG наложения
рисует малый вертел красным; при нулевой маске ручной контур отображается пунктиром,
если он есть. Маска сохраняется отдельно. `quality_scores` — эвристические оценки,
не калиброванные вероятности.

На PNG точки бедра обозначены 1/2/3, подвздошные точки — L/R относительно снимка.
Русская расшифровка содержится в `annotation_legend`. Для ручного разметчика доступны
`GET /v1/data/images/{id}/preview.png` и
`GET /v1/data/images/{id}/annotation/{version}/overlay.png`.

Выгрузка: `GET /v1/jobs/{job_id}/export?format=zip` (также json/csv).
Ошибка одного снимка не прерывает папку; ошибки включены в выгрузку.
CPU чтение и GPU батчи ограничены по памяти. Для каждого модуля GPU измеряет память
одного настоящего forward, выбирает батч с запасом; при OOM делит батч пополам.
Профиль и фактические батчи доступны в результате задания.

## Ручная разметка и очередь

1. `POST /v1/data/import?path=...` или `/v1/data/uploads` возвращает image_id.
2. `PUT /v1/data/images/{id}/annotation` принимает:

```json
{
  "region":"LEG_LEFT",
  "geometry":{},
  "reviewed":["hip"],
  "targets":{"hip_rotation":0},
  "expected_version":0
}
```

Вместо `{}` передайте полную геометрию формата `labeler.geometry` из разметчика
или geometry.json результата, исправленную человеком. Для повторного редактирования
expected_version берётся из текущего состояния изображения. Геометрия проверяется,
ROI и линии нормализуются. Опционально можно передать `spacing_mm:[1.05,0.6]` (Y,X).

Разделы `reviewed`: `spine` (линии и подвздошные точки), `artifact` (боксы),
`hip` (вся геометрия бедра), `hip_points` (только три точки). Непроверенный модуль
не дообучается на таком примере; отсутствующая структура в проверенном разделе
означает подтверждённое отсутствие. Для аугментации требуется проверенный spine/hip.

Если берёте сокращённую геометрию из JSON предсказания, добавьте
`mask_result_id:"ID результата"`: сервис загрузит соответствующую PNG-маску и проверит
её принадлежность снимку. Полный geometry.json уже содержит пиксели и не требует
этого поля. После изменения линий малого вертела сбросьте
`lesser_trochanter_mask_ready=false`, чтобы маска была пересчитана по новым линиям.

3. `POST /v1/data/queue`:

```json
{
  "image_id":"ID",
  "annotation_version":1,
  "request_id":"уникальный-ID-запроса",
  "config":{
    "positive_count":5,
    "negative_count_by_target":{"hip_position":5,"hip_roi":5},
    "negative_source_count":5,
    "seed":42,
    "max_attempts_per_sample":100
  }
}
```

Для позвоночника доступны spine_position и spine_axis. Уже негативный источник
получает negative_source_count вариантов, сохраняющих исходное нарушение.
Все метки пересчитываются совместно; невыполнимые квоты явно перечислены в отчёте.
Артефакты и ротация бедра отдельно не синтезируются. Идентичные пиксели внутри
одного задания не добавляются повторно. Разметка и масштаб преобразуются вместе
со снимком. `POST /v1/data/augmentation` делает то же без помещения в очередь.

`GET /v1/data/queue?status=ready` показывает готовые примеры. Повтор request_id
с тем же содержимым возвращает то же задание; с другим содержимым — ошибку.

## Дообучение и активация

`POST /v1/model/partial_fit`:

```json
{"replay_per_task":32,"learning_rate":0.00002}
```

Можно указать base_model_version и queue_ids; иначе берутся активная модель
и готовая очередь. В очередь следующего запуска не включаются новые поступления
во время уже начатого обучения. Модули стартуют с исходных весов, добавляется replay
старых train-исследований. Новые исследования очереди закрепляются за train;
существующие validation/test сохраняются. Для полностью нового обучения нужно
сначала сформировать отдельный стратифицированный протокол.

Проверяется принадлежность исследований и совпадение пикселей с контролем.
Контрольные исходники и их аугментации отклоняются. Все эпохи наследуются из паспорта;
оптимизатор новый. Проверяются функции потерь/боксы модулей и полный пайплайн на
validation: F1, ROC AUC, покрытие, интервалы по исследованиям. Порог ротации
перекалибруется на validation в мм². Test в подборе новой версии не участвует.

Кандидат проходит gate: модульные метрики без существенного ухудшения, падение
macro-F1 и покрытия полного пайплайна не более 0.02. Новая версия никогда не
активируется автоматически: `POST /v1/model/versions/{version}/activate`.
У прошедшей версии очередь consumed; при неудачной проверке очередь снова ready.
Для отката активируйте предыдущую версию. Валидация при малом количестве независимых
исследований остаётся внутренней оценкой, не внешним тестом.

## Проверки

```powershell
.venv\Scripts\python.exe -m pytest dxa_project/tests/test_service.py -q
.venv\Scripts\python.exe -m dxa_project.service.smoke
```

Smoke использует предыдущие готовые веса, три области, CPU и отдельную папку
`outputs/service_smoke`. Дообучение в smoke — ровно одна эпоха на модуль,
не обычный бюджет сервиса и не эксперимент по оценке качества.
Не добавляйте `service_data` в git: там DICOM, разметка, очередь и веса.
## Итоговый пакет и пофайловые логи

Новая сборка: `../outputs/final_20260929/bundle`; протокол:
`../outputs/final_20260929/protocol.json`. Помимо пяти основных весов пакет
содержит `scoliosis.pt`, `hip_mask.pt` и при улучшении validation — `spine_crests.pt`
(отдельные подвздошные ориентиры). Они сохраняются при регистрации модели и
используются в пакетном предсказании. Эти дополнительные модули пока сохраняются
при partial_fit без дообучения.
Результат позвоночника содержит `quality_flags.spine_scoliosis`, непрерывный
`quality_scores.spine_scoliosis` и объект `scoliosis` с порогом решения.
Сколиоз — локальная метка разметки, отдельно от общего наклона оси.

Worker выводит «Фотография 1/N: обработка», затем «готово» или «ошибка».
События сохраняются в `jobs/<job_id>/prediction.jsonl`; читать их можно через
`GET /v1/jobs/<job_id>/logs?offset=0&limit=100`. Ответ содержит `events`,
`next_offset`, `total`. Во время обработки `GET /v1/jobs/<job_id>` показывает
счётчик и текущий файл. Сбой отдельного DICOM сохраняется в логах и не мешает
предсказанию остальных файлов. При запуске worker через `python -m
dxa_project.service.worker` информационные сообщения выводятся в консоль.

`partial_fit` дообучает пять основных модулей. Дополнительные scoliosis,
hip_mask и spine_crests сохраняются без изменения; их обновление выполняется отдельным
полным версионным обучением.
