# Что публиковать в Git

## Для просмотра командой

Самодостаточный отчёт: **вся папка `dxa_project/team_demo/`**. В ней HTML,
PNG-примеры, агрегированные метрики и пять наборов итоговых ответов.
Скопировать только index.html недостаточно — рядом нужна папка images.
После clone открыть index.html в браузере. GitHub показывает HTML как код;
чтобы просмотреть страницу, скачать/клонировать репозиторий и открыть локально.

В отчёте 35 примеров отдельных модулей и 5 полных проходов; примеры используют
11 разных исходных снимков. Для каждого модуля показано по 5 примеров.
В них есть успехи и ошибки. Это статический показ уже выполненного инференса.

## Для совместной разработки

Добавить следующие пути:

- `dxa_project/geometry_ml/`: модели, обучение, инференс, оценка, отчёты и тяжёлый вариант;
- `dxa_project/augmentation/`: генерация, геометрия позвоночника и документация;
- `dxa_project/tests/*.py`: автоматические проверки;
- `labeler/*.py`, Dockerfile, docker-compose.yml, requirements.txt, README.md и примеры .env;
- `dxa_project/prepare.py`, `run_augmented_experiment.py`, `README.md`;
- `dxa_project/DXA_augmented_pipeline.ipynb`: ноутбук с командами и чтением отчётов;
- `dxa_project/requirements-geometry.txt` и этот файл.

Не добавлять все outputs, backups, исходные DICOM, разметку целиком, архивы,
личные .env или веса моделей. Для собственного запуска инференса команде нужны
`router.pt`, `spine.pt`, `hip.pt`, `artifact.pt` и `evaluation/calibration.json`:
передать их отдельно с сохранением структуры папки. Для обучения нужны данные,
labels.csv, geometry JSON и подготовленный manifest.csv — их нет в демонстрационной поставке.
Физический размер пикселя пока номинальный.

## Готовая папка для загрузки

Из корня проекта:

```powershell
.venv\Scripts\python.exe -m dxa_project.geometry_ml.export_team_bundle
```

Результат: `dxa_project/outputs/git_team_bundle/`. Это чистая поставка по явному
списку файлов; `FILES.json` содержит размеры и SHA256. Внутри сохранена структура
путей проекта. Скопировать **содержимое** этой папки в отдельный checkout и
закоммитить его. Так в commit не попадут старые локальные outputs и разметка.

Удалённый репозиторий текущего проекта: `https://github.com/Pershin-A/CV-Medicine.git`.
Загрузка пока не выполнена. В текущем checkout уже отслеживаются некоторые
файлы разметки и outputs; простое добавление их в .gitignore не убирает их из
истории или индекса. Поэтому для публикации этой работы лучше использовать
подготовленную поставку и проверить `git diff --cached --stat` перед commit.

Для публикации только демонстрации из текущего checkout:

```powershell
git add -- dxa_project/team_demo dxa_project/GIT_PUBLICATION.md
git diff --cached --stat
```

Эти команды не выполняют commit/push. Если в индексе уже есть посторонние файлы,
они тоже появятся в diff: не включайте их в commit случайно.
