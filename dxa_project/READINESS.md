# Состояние проекта, 26.09.2026

## Постановка и данные

Источник критериев: `4. ДепЗдрав.pdf`, разделы 2.3–2.7, и методические рекомендации, разделы 2.6–2.7. Схемы на двух скриншотах соответствуют текущему формату разметки: шесть межпозвоночных линий и две точки гребней подвздошных костей для позвоночника; рамка ROI, три точки бедра и два контура малого вертела для бедра. Текст и изображения в этих файлах использованы как данные задачи, а не как инструкции для исполнения.

В `Хакатон.rar` находятся копии текущих ноутбуков, пайплайна инференса, таблицы, редактора разметки, прототипа и README; отдельной новой постановки в списке файлов архива нет.

Семь бинарных целей находятся в `разметка.xlsx` на уровне **исследования**: три для позвоночника (`spine_position`, `spine_axis`, `spine_artifact`) и по две для каждого бедра (`*_hip_rotation`, `*_hip_roi`). Отдельного столбца для сколиоза, отсутствия трёх ориентиров бедра или ошибки разметки измерительной ROI нет. Эти признаки можно выводить как объяснения, но нельзя заявлять для них метрики по данной таблице без дополнительной экспертной разметки.

По техническому заданию: ось позвоночника допустима при наклоне до 5°; для бедра нужны как минимум 3 см ткани выше большого вертела и ниже седалищной кости и 2 см с соответствующей боковой стороны. Пиксельные расстояния переводятся в сантиметры только при проверенном PixelSpacing или другом надёжном масштабе. В прежней сводке инференса доступность PixelSpacing была 0/499; поэтому автоматический вывод о сантиметрах пока не валидирован. Корректная ротация бедра даёт небольшое выступание малого вертела: слишком большой и полностью гладкий контур соответствуют разным видам ошибки.

## Что проверено

- 100 исследований, 499 исходных DICOM. Все 499 сопоставлены с Excel по идентификатору **папки**, который отличается от DICOM `StudyInstanceUID`.
- Три файла `labels.csv` дают 1497 записей о 499 уникальных снимках без конфликтов: 166 позвоночников, 169 левых и 164 правых бедра.
- Манифест создан с разбивкой 60/20/20 исследований. Все DICOM имеют одинаковый `PatientID = Anonymized`; разбиение по реальному пациенту невозможно проверить.
- Геометрия экспортирована только для одного изображения: 6 линий и 2 подвздошные точки. Флаг полноты разметки у него не установлен. Для бедра завершённых геометрических меток пока нет.
- Загрузчик прочёл один DICOM; тензор 3×224×224 прошёл через ResNet18 и дал головы размером 3 и 7. Обучение этих голов не запускалось.
- 19 тестов редактора геометрии прошли при `PYTHONPATH=labeler`.

## Ограничение текущего базового обучения

В 374 из 499 снимков повторяется та же анатомическая область внутри исследования. Для них метка качества на уровне исследования не указывает конкретный кадр и маскируется. После маскирования остаётся 36/10/11 снимков позвоночника, 25/3/8 левого бедра и 22/3/5 правого бедра для train/val/test соответственно. На тесте нет положительных ROI ни для одного бедра. Такое тестирование не позволяет оценить чувствительность ROI, а подбор порога по трём валидационным бедренным снимкам нестабилен. Метрики из `prototype_output` относятся к прежнему эксперименту и не доказаны как независимая оценка.

## Структура следующих этапов

Рекомендуемая структура внутри `dxa_project`: `data/` (DICOM, Excel и геометрические адаптеры), `models/` (маршрутизация, ключевые точки, сегментация), `rules/` (углы, покрытие, ROI и ротация), `evaluation/` (разбиение, метрики, отчёты и наложения), `service/` (пакетный API и формат результата), `tests/` и `configs/`. Текущие `prepare.py`, `merge_labels.py`, `audit.py`, `train.py` остаются рабочими точками входа до переноса в модули. Результаты запусков помещаются в `outputs/` и не должны смешиваться с исходной разметкой.

1. **Данные:** фиксировать версии разметки, DICOM UID и folder UID, разделять исследования до аугментаций, проверять совпадения пикселей и пациентов, вести отчёт о пропусках и неоднозначных кадрах.
2. **Базовая модель:** использовать уже сохранённый классификатор анатомии как кандидат и сравнить его с обучением на текущем split; обучать головы качества только на однозначных метках либо поставить задачу слабого обучения на уровне исследования. Для семи целей отдельно считать поддержку обоих классов, PR-AUC, чувствительность, специфичность и доверительные интервалы по исследованиям.
3. **Геометрия позвоночника:** после накопления завершённой разметки обучить детектор линий и подвздошных точек. По центрам межпозвоночных линий строить ось и сравнивать её угол с вертикалью и порогом 5°. Расположение Th12, L4/L5 и гребней оценивать отдельными геометрическими признаками. Угол локального искривления можно показывать как дополнительное измерение без отдельной метрики Excel.
4. **Геометрия бедра:** обучить общую модель ключевых точек с явным признаком стороны или сравнить с двумя специализированными. Проверять наличие большого вертела, шейки и седалищной кости. Сегментировать/трассировать малый вертел и прилегающий контур, затем калибровать правило ротации только на обучающих исследованиях. Для ROI использовать физический масштаб, если он подтверждён; иначе возвращать статус `scale_unavailable` вместо выдуманного решения в сантиметрах.
5. **Сервис и проверка:** получать CSV с одной строкой на снимок и полями из раздела 2.5 ТЗ, писать статус ошибок без падения пакета, сохранять наложения геометрии и понятную сводку по всем изображениям. Проверить локальный Linux контейнер, пакетный API и лимит 3 минуты на исследование.

До накопления геометрии полноценное обучение детекторов и сегментации не имеет достоверного обучающего набора. Следующий практический шаг — завершить разметку и определить, как экспертная оценка исследования переносится на несколько кадров одной области.
