# DXA Quality Control — разметка и прототип анализа DXA

Исследовательский проект для ручной разметки и экспериментального анализа DICOM-изображений поясничного отдела позвоночника и проксимального отдела бедренной кости.

В проекте две независимые части:

- **`labeler/`** — браузерное приложение **DXA DICOM Labeler v5.3** на Streamlit, запускаемое через Docker. Оно сохраняет категориальные метки, геометрическую разметку и порог визуализации для каждого изображения.
- **`prototype/` и файлы в корне** — ноутбуки и скрипты с экспериментальными алгоритмами компьютерного зрения и машинного обучения. **Для запуска приложения разметки они не нужны.**

> Приложение предназначено для исследовательской разметки и контроля качества данных. Оно не ставит диагноз и не заменяет решение специалиста. Исходные DICOM должны оставаться в отдельном защищённом каталоге.

## 1. Быстрый запуск приложения разметки (Windows + Docker Desktop)

### 1.1. Что установить

1. Установите **Docker Desktop** и запустите его. На Windows используйте Linux containers; при необходимости включите WSL 2.
2. Убедитесь, что команда `docker compose version` работает в **PowerShell**. Отдельно устанавливать Python, Streamlit или библиотеки для DICOM **не нужно**: они устанавливаются при сборке Docker-образа.
3. Распакуйте архив проекта, например, с помощью **7-Zip**. Архив `.rar` нельзя распаковать командой PowerShell `Expand-Archive`.

### 1.2. Подготовьте каталоги

Разместите исходные исследования и результаты **рядом** с папкой `labeler`:

```text
Хакатон/
├── labeler/
│   ├── app.py
│   ├── docker-compose.yml
│   ├── Dockerfile
│   ├── .env.example
│   └── ...
├── Исследования/           # исходные DICOM, вложенные папки допустимы
├── Размеченные/            # сюда приложение записывает результат
└── разметка.xlsx           # справочная экспертная таблица
```

В присланном архиве **есть `разметка.xlsx`**, но **нет полного каталога `Исследования/` и прежних результатов `Размеченные/`**. Положите свои DICOM в `Исследования/`. Каталог `Размеченные/` создайте, если его ещё нет. Не удаляйте существующую папку с разметкой при обновлении приложения.

Из корня проекта можно создать папки командой:

```powershell
New-Item -ItemType Directory -Force .\Исследования, .\Размеченные
```

### 1.3. Настройте пути в `.env`

Откройте PowerShell **в корне проекта** и выполните:

```powershell
cd .\labeler
Copy-Item .env.example .env
notepad .env
```

Параметры по умолчанию из этого проекта:

```dotenv
DXA_DATA_DIR=../Исследования
DXA_OUTPUT_DIR=../Размеченные
DXA_REFERENCE_XLSX=../разметка.xlsx
EXPECTED_DICOM_COUNT=499
EXPECTED_DATASET_FINGERPRINT=
STRICT_DATASET_CHECK=1
```

| Параметр | Для чего нужен |
|---|---|
| `DXA_DATA_DIR` | Каталог исходных DICOM. Монтируется в `/data` **только для чтения**. |
| `DXA_OUTPUT_DIR` | Каталог результатов. Монтируется в `/output` с правом записи. |
| `DXA_REFERENCE_XLSX` | Экспертная таблица, монтируется в `/reference/разметка.xlsx`. |
| `EXPECTED_DICOM_COUNT` | Ожидаемое число DICOM: в исходной конфигурации **499**. Для другого набора укажите его фактическое число; `0` отключает только проверку количества. |
| `EXPECTED_DATASET_FINGERPRINT` | Необязательная контрольная сумма перечня относительных путей и размеров файлов. Пустое значение отключает проверку суммы. |
| `STRICT_DATASET_CHECK` | `1`: при несоответствии набора разметка останавливается; `0`: выдаётся предупреждение, но можно продолжать. |

**Все относительные пути в `.env` отсчитываются от папки `labeler/`, где лежит `docker-compose.yml`.** Если каталоги у вас расположены иначе, измените эти три пути. Для совместной работы нескольких разметчиков рекомендуется зафиксировать ожидаемое число файлов и fingerprint одного и того же набора.

Если у вас нет `разметка.xlsx`, текущая конфигурация Compose всё равно пытается смонтировать **файл** по указанному пути. Предоставьте файл либо удалите соответствующий bind mount из `docker-compose.yml`: само приложение умеет работать без экспертных подсказок и покажет предупреждение, что Excel не найден.

### 1.4. Соберите и запустите контейнер

Находясь в `Хакатон/labeler/`:

```powershell
docker compose config
docker compose up -d --build
```

`docker compose config` выводит итоговую конфигурацию, включая разрешённые пути к каталогам. После запуска проверьте состояние и журнал:

```powershell
docker compose ps
docker compose logs --tail 100 dxa-labeler
```

Откройте в браузере **http://localhost:8501**. При первом запуске Docker скачает базовый образ Python и установит зависимости, поэтому сборка может занять несколько минут.

Порт в `docker-compose.yml` задан как `8501:8501`. Если он уже занят, замените на `8502:8501` и открывайте `http://localhost:8502`.

### 1.5. Убедитесь, что данные подключились

```powershell
# Число DICOM и fingerprint; manifest сохраняется в папке Размеченные/
docker compose exec dxa-labeler python dataset_manifest.py /data --out /output/dataset_manifest.csv

# Проверить доступность Excel
docker compose exec dxa-labeler python -c "from pathlib import Path; print(Path('/reference/разметка.xlsx').is_file())"
```

Если появилось сообщение о несоответствии количества DICOM, исправьте `EXPECTED_DICOM_COUNT` в `.env` на реальное число (или `0`) и пересоздайте контейнер:

```powershell
docker compose up -d --force-recreate
```

Ожидаемое значение `499` относится только к исходному набору, использованному при разработке, и не является обязательным для других датасетов.

## 2. Как пользоваться редактором

1. В левой панели выберите DICOM из списка или найдите файл по имени. Доступны переходы к предыдущему/следующему снимку и индикатор прогресса.
2. В разделе **«Класс»** выберите **«Позвоночник»** или **«Нога»**. Укажите категориальные метки и при необходимости сторону бедра, разметчика и комментарий.
3. Выберите инструмент и поставьте анатомические ориентиры прямо на изображении:

| Для позвоночника | Управление | Что сохраняется |
|---|---|---|
| Межпозвонковая линия | **2 одиночных клика** — начало и конец; можно добавить несколько линий | `spine.disc_lines` |
| Верхние края подвздошных костей — слева/справа **на изображении** | **1 клик** для каждой точки | `spine.iliac_crests` |
| Посторонний предмет | **2 клика** по противоположным углам прямоугольника; тип: металл / одежда / другое | `spine.foreign_objects` |

| Для бедра | Управление | Что сохраняется |
|---|---|---|
| 1 — большой вертел; 2 — шейка бедра; 3 — седалищная кость | **1 клик** на каждый ориентир | `hip.landmarks` |
| Карандаш: малый вертел | Зажмите левую кнопку мыши, обведите и отпустите | `hip.lesser_trochanter_traces.trochanter` |
| Карандаш: контур кости рядом | Зажмите кнопку мыши, проведите линию и отпустите | `hip.lesser_trochanter_traces.adjacent_bone` |
| Прямоугольная область интереса (ROI) | **2 клика** по противоположным углам | `hip.roi_box` |

Для точной обводки малого вертела используйте масштаб 200–300%. Каждый свободный штрих сохраняется как **полилиния**, а не как автоматически закрашенная сегментационная маска. Полигоны, созданные в прежних версиях, остаются доступными.

4. Можно переключиться с вида **«Оригинал»** на **«Порог + граница»**, выбрать слайдером уровень яркости **0–255**. Подсветка пикселей и границ появляется поверх изображения; порог сохраняется отдельно для каждого DICOM после сохранения. Это порог **нормализованного 8-битного предпросмотра**, а не значение минеральной плотности костной ткани.
5. Для исправлений доступны **«Удалить кликом»**, крестик у объекта в постоянной строке, **«Отменить» / «Повторить»**, а также очистка текущего слоя с подтверждением. Разметку можно отметить завершённой отдельно для текущей анатомической области.
6. Нажмите **«Сохранить»** или **«Сохранить и следующий →»**. Рисование в браузере само по себе не заменяет сохранение на диск.

Приложение также показывает доступные сведения из `разметка.xlsx` по текущему исследованию. Это справочная информация, а не автоматическое присвоение всех меток.

## 3. Где хранятся результаты

Приложение **не изменяет исходные DICOM** в `/data`. При сохранении данные попадают в `Размеченные/` (то есть в `/output` внутри контейнера):

```text
Размеченные/
├── labels.csv                         # основной актуальный реестр: 1 строка на файл
├── labels.csv.bak                     # резервная копия предыдущего CSV
├── labels_history.csv                 # история изменений категориальной разметки
├── geometry/
│   ├── <sha256_относительного_пути>.json  # геометрия данного изображения
│   └── geometry_history.jsonl         # история геометрических разметок
├── <относительный путь исходного DICOM>.dcm  # размеченная копия
└── dataset_manifest.csv               # только если вы создавали его командой выше
```

В `labels.csv` хранятся `relative_path`, `label` (`SPINE` / `LEG` / `UNKNOWN`), `side`, `metal`, `fracture`, `spine_issue`, `notes`, `annotator`, `annotated_at`, ссылки на результаты и признак завершённости геометрии. Геометрия хранится отдельно в JSON и также записывается в private DICOM metadata размеченной копии. Старый `labels.csv` читается без отдельной миграции.

Координаты линий, точек, контуров и ROI сохраняются **в пикселях исходного DICOM**: начало координат — верхний левый угол, `x` направлена вправо, `y` — вниз. Масштаб редактора на координаты в экспорте не влияет.

### Экспорт геометрии для ML

В `labeler/` выполните:

```powershell
docker compose exec dxa-labeler python export_geometry.py --output-root /output
```

Будут созданы:

- `Размеченные/annotations_geometry.jsonl` — по одной записи с полной геометрией на изображение;
- `Размеченные/annotations_geometry_summary.csv` — сводные поля, размеры и количество объектов.

Экспортируется содержимое `labels.csv` с указанным и существующим `geometry_path`.

## 4. Остановка, обновление и диагностика

```powershell
# Остановить сервис, не удаляя папки с исходными DICOM и разметкой
docker compose down

# Запустить существующий образ
docker compose up -d

# Пересобрать после изменения кода в app.py или dxa_canvas/
docker compose up -d --build --force-recreate

# Посмотреть ошибки
docker compose logs -f --tail 100 dxa-labeler
```

**Перед обновлением приложения сделайте резервную копию всей папки `Размеченные/`.** Затем замените исходники в `labeler/`, сохраните ваш `.env`, выполните пересборку и обновите страницу браузера через `Ctrl+F5`. Если после обновления показывается старая версия интерфейса, проверьте пересборку образа и кэш браузера.

Типовые проблемы:

| Симптом | Что проверить |
|---|---|
| Приложение не открывается | Docker Desktop запущен, `docker compose ps`, `docker compose logs`; порт 8501 свободен. |
| В `/data` нет DICOM | `DXA_DATA_DIR`, расположение `Исследования/`, доступ Docker к локальному диску. |
| Проверка набора остановила разметку | `EXPECTED_DICOM_COUNT`, fingerprint, `STRICT_DATASET_CHECK`; перечень файлов в `dataset_manifest.csv`. |
| Ошибка монтирования Excel | Реально существует ли файл, указанный в `DXA_REFERENCE_XLSX`. |
| Изменения не видны после редактирования кода | Пересборка `--build --force-recreate`, затем `Ctrl+F5`. |
| Отсутствуют новые сохранённые объекты | Нажата ли кнопка «Сохранить»; правильный ли `DXA_OUTPUT_DIR`. |
| DICOM не декодируется | Проверьте журнал и установленный кодек: проект включает `pydicom` и `pylibjpeg-libjpeg`, но поддержка конкретного синтаксиса передачи зависит от фактического файла. |

│   ├── .dockerignore                     # исключения при сборке образа
│   ├── .gitignore                       # исключения Git внутри labeler/

**Примечание о версиях:** в приложенном архиве фактически находится `prototype/DXA_prototype_v5_5.ipynb`. Вложенный `prototype/README.md` всё ещё упоминает `v5_3` — это устаревшее имя файла. Для Docker-приложения исследовательские ноутбуки не требуются.

## 6. Отдельный исследовательский прототип (не обязателен для разметки)

В `prototype/` находятся алгоритмы проверки укладки, геометрии позвоночника и бедра, а также эксперименты с классификаторами. Для них создайте **отдельное Python-окружение** и устанавливайте `prototype/requirements.txt` вне контейнера labeler; часть экспериментов использует PyTorch и предобученные модели.

```powershell
# Из корня проекта; Python 3.11 рекомендуется для отдельного окружения
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r .\prototype\requirements.txt
python -m pip install jupyterlab
jupyter lab .\prototype\DXA_prototype_v5_5.ipynb
```

Отдельный `dxa_inference_pipeline.py` принимает подготовленные checkpoint или объединённый bundle; сам по себе не обучает модели. Изображения и checkpoint для его инференса необходимо предоставить отдельно. Примеры аргументов доступны в начале файла и через `python dxa_inference_pipeline.py --help`.

## 7. Конфиденциальность и Git

Не публикуйте реальные DICOM, `Размеченные/`, `.env`, экспертную таблицу и checkpoint. **В текущем корневом `.gitignore` некоторые строки (`Размеченные/`, `разметка.xlsx`, `*.dcm`) закомментированы.** Перед любым commit исправьте `.gitignore`, а также проверьте, что файлы с персональными/медицинскими данными не были добавлены ранее (одного `.gitignore` недостаточно для уже отслеживаемых файлов). Ноутбуки могут содержать сохранённые графики и результаты: их тоже следует проверить.

```powershell
git status --short
```

При передаче проекта предоставляйте код и инструкции отдельно от медицинских данных. Результаты ручной разметки и пороги яркости предназначены для обучения и проверки алгоритмов; они не являются самостоятельным клиническим заключением.
