# DXA DICOM Labeler — v5.3 (тонкий карандаш и порог яркости)

Это **расширение исходного Streamlit/Docker-приложения**, а не замена существующей
разметки. Сохраняются прежние метки `SPINE` / `LEG` / `UNKNOWN`, сторона бедра,
металл, перелом, состояние позвоночника, поиск, навигация, Excel-подсказки,
`labels.csv`, `labels_history.csv` и размеченные копии DICOM.

## Обновление существующего приложения

1. **Сделайте резервную копию всей папки `Размеченные/`** (включая `labels.csv`).
2. Распакуйте папку `labeler/` из архива рядом с существующими `Исследования/`
   и `Размеченные/`. Используйте новую папку как исходники приложения.
3. Скопируйте ваш **локальный** `.env` из старой папки `labeler/` в новую;
   в архив он не включён. Проверьте `DXA_DATA_DIR`, `DXA_OUTPUT_DIR` и
   `DXA_REFERENCE_XLSX`. При отсутствии `.env` создайте его из `.env.example`.
4. Если текущий набор содержит не 499 DICOM, установите реальное значение
   `EXPECTED_DICOM_COUNT` или `0` для отключения только этой проверки. При
   указанном fingerprint он должен соответствовать вашему набору.
5. Из новой папки `labeler/` выполните:

```powershell
docker compose down
docker compose up -d --build --force-recreate
```

Откройте `http://localhost:8501`. Исходные DICOM по-прежнему монтируются в
контейнер `read_only`; запись идёт только в `Размеченные/`. Старый `labels.csv`
читается без предварительной миграции, новые колонки добавляются при сохранении.

**Важно:** в архиве только исходники. Настоящие DICOM, существующий `.env`,
`разметка.xlsx` и прежние результаты разметки не включены.

## Изменения версии 5.3

### Тонкий карандаш вместо точечного полигона малого вертела

Для класса «Нога» добавлены два **независимых инструмента**:

- **«Карандаш: малый вертел»** — обвести непосредственно малый вертел (тонкая жёлтая линия).
- **«Карандаш: контур кости рядом»** — провести линию по соседнему контуру бедренной кости (тонкая розовая линия).

Зажмите левую кнопку мыши, ведите курсор вдоль нужной границы, затем отпустите.
Штрих сохраняется **одним действием при отпускании**, без дополнительного подтверждения.
Толщина визуальной линии составляет 1.25 px в координатах PNG-превью; крупные
опорные кружки не рисуются. Возможны несколько раздельных штрихов на каждом слое,
удаление одного штриха через постоянную строку объектов, «Удалить кликом»,
Undo / Redo и очистка текущего слоя с подтверждением. При необходимости
увеличьте изображение до 200–300% перед обводкой.

Новые штрихи хранятся в исходных координатах DICOM:

```json
{
  "hip": {
    "lesser_trochanter_traces": {
      "trochanter": [{"id": "a1", "points": [[100, 150], [101, 152], [103, 155]]}],
      "adjacent_bone": [{"id": "a2", "points": [[120, 150], [121, 153]]}]
    }
  }
}
```

Этот фрагмент показывает только новые поля; реальный JSON содержит также прежние
поля разметки. **Старые полигоны v5.2 не удаляются:** `hip.lesser_trochanter`
остаётся доступным при чтении, отображается пунктиром и может быть удалён вручную.
При рисовании карандашом сохраняется полилиния (отдельная маска автоматически
не строится), что позволяет затем использовать обводку как анатомическую границу.

### Режим «Порог + граница»

В отдельной постоянной строке редактора появился переключатель «Оригинал» /
«Порог + граница» и слайдер **0–255**. В пороговом виде исходное DXA остаётся
видимым; пиксели с яркостью **≥ порога** подсвечиваются полупрозрачным бирюзовым,
а граница бинарной области — оранжевой тонкой линией. Ползунок обновляет картинку
в реальном времени. При отпускании ползунка значение передаётся в Streamlit.

Для каждого DICOM отдельно сохраняется поле:

```json
"image_view": {"mode": "threshold", "threshold_8bit": 137}
```

Значение и режим восстанавливаются при повторном открытии изображения после
нажатия **«Сохранить»** в основной форме. Порог также включён в экспортный CSV
и полный JSONL. Слайдер работает и на позвоночнике, и на бедре.

**Что означает 0–255:** это яркость нормализованного для отображения 8-битного
изображения. Сначала применяется DICOM rescale/VOI LUT (при наличии), затем
нормализация по 1-му и 99-му процентилям и инверсия MONOCHROME1 (при необходимости),
затем создаётся PNG-превью; если исходное изображение очень большое, превью
уменьшается LANCZOS. Порог применяется именно к этому превью. Это **не единицы
минеральной плотности кости и не диагностический порог**. Если требуется
пиксельно точный порог на полном разрешении, его следует пересчитать из
исходных DICOM-пикселей с учётом описанной нормализации и ресэмплинга.

Новые поля необязательны для старых sidecar JSON; при чтении подставляются
пустые штрихи и стандартное отображение с порогом 128. Версия схемы сохранена
равной 1 для обратной совместимости. Служебная ревизия событий v5.2 и защита
от запоздавших ответов Streamlit сохранены. HTML-компонент имеет новый ключ
`dxa_canvas_v53` для обновления фронтенда без загрузки старой версии из кэша.

## Изменения версии 5.2 (сохранены)

- **Исправлено исчезновение и повторное появление объектов после клика.** В прежней версии Streamlit мог прислать компоненту задержавшийся снимок разметки; браузер принимал его за новое состояние и откатывал изменения. Теперь при работе с одним DICOM редактор хранит актуальную геометрию локально и не перезаписывает её запаздывающими подтверждениями от Streamlit.
- **Исправлено удаление по кнопке ×.** Сохранение, последовательное удаление нескольких объектов и работа Undo/Redo используют одну актуальную копию разметки; старый снимок не восстанавливает удалённые объекты.
- В каждое сообщение редактора добавлен монотонный служебный номер изменения. Python принимает только новые версии; номер не записывается в JSON разметки, DICOM или таблицу. Сохранён формат и совместимость разметки v5.0/v5.1.
- Добавлен браузерный регрессионный тест: несколько линий и точек, запоздавшие ответы Streamlit, однократные удаления кнопкой ×, переключение области и сохранение стабильных размеров интерфейса.
- Для обновления кэшированного HTML-компонента изменён ключ Streamlit на `dxa_canvas_v52`.

### Изменения версии 5.1, сохранённые в 5.2

- Инструменты находятся в **двух фиксированных строках**. Выбор типа предмета размещён во второй строке после «Предмет: прямоугольник» и «Удалить кликом» и не двигает снимок.
- Строка объектов есть **всегда**, в том числе пустая; содержит линии, обе точки подвздошных костей, рамки предметов, ключевые точки бедра, контур малого вертела и ROI. При большом количестве объектов прокручивается горизонтально.
- Обработка ввода переведена на одиночное событие `pointerdown`: одна точка/удаление — один клик, линия/прямоугольник — два последовательных клика. «Очистить текущий слой» по-прежнему требует осознанного подтверждения, так как действие массовое.
- Окно редактора по высоте **820 px**; изображение при масштабе 100% вписывается по доступной ширине и высоте (до 810 px), а не отображается в исходном уменьшенном размере превью. Соотношение сторон и координаты исходного DICOM сохраняются.
- Изменена пропорция колонок: редактору отведено больше горизонтального пространства. Новая версия компонента имеет отдельный UI-key для обновления кэша Streamlit.
- **Формат данных не менялся**: `labels.csv`, JSON геометрии, DICOM private tag, история и экспорт остаются совместимыми с v5.0.

## Инструменты геометрической разметки

Выберите класс «Позвоночник» или «Нога», после чего слева появляется редактор.

| Класс | Инструмент | Действие мышью | Сохраняемое поле |
|---|---|---|---|
| Позвоночник | Межпозвонковая линия | Два клика в начале и конце линии; количество линий произвольное | `spine.disc_lines[].points` |
| Позвоночник | Край подвздошной кости слева / справа | По одному клику на каждой видимой верхней части, **слева/справа на изображении** | `spine.iliac_crests` |
| Позвоночник | Посторонний предмет | Два последовательных клика по противоположным углам; категория металл / одежда / другое | `spine.foreign_objects[]` |
| Бедро | 1 — большой вертел | Один клик, повторный меняет координаты | `hip.landmarks.greater_trochanter` |
| Бедро | 2 — шейка бедра | Один клик | `hip.landmarks.femoral_neck` |
| Бедро | 3 — седалищная кость | Один клик | `hip.landmarks.ischial_bone` |
| Бедро | Карандаш: малый вертел | Зажать и провести тонкую линию по вертелу | `hip.lesser_trochanter_traces.trochanter[]` |
| Бедро | Карандаш: контур кости рядом | Зажать и провести тонкую линию по соседнему контуру кости | `hip.lesser_trochanter_traces.adjacent_bone[]` |
| Бедро | Bounding box области интереса | Два последовательных клика по противоположным углам | `hip.roi_box` |

Отдельно доступны Undo / Redo, очистка активного слоя (с подтверждением),
удаление одним кликом по объекту и удаление любой метки по кнопке × в постоянной строке объектов.
Масштаб просмотра 75–300%, окно просмотра высотой 820 px и прокрутка увеличенного изображения.

**Важно для ROI:** создаваемый прямоугольник — ручная эталонная разметка
области, а не восстановление исходного ROI денситометра из DICOM. Перед
сохранением можно отметить чекбокс «Геометрическая разметка этой области
завершена». Пустая разметка без этой отметки означает **не размечено**, а
не отрицательный клинический пример.

### Координаты и файлы

Координаты всех точек сохраняются в **исходной пиксельной системе DICOM**:
`(0,0)` — левый верхний угол матрицы, `x` вправо, `y` вниз. Уменьшение
изображения на экране не меняет координаты аннотаций. Все геометрические
координаты следует рассматривать относительно той ориентации, в которой
изображение было декодировано приложением.

Для каждого сохранения создаются/обновляются:

```text
Размеченные/
├── labels.csv                   # прежние метки + geometry_path и флаги завершения
├── labels_history.csv           # история табличных меток
├── geometry/
│   ├── <sha256(relative_path)>.json  # полная анатомическая разметка
│   └── geometry_history.jsonl        # снимок геометрии при каждом сохранении
└── <исходные подпапки>/<имя>.dcm  # DICOM-копия с private tags, включая Geometry JSON
```

`spine`, `hip` и индивидуальный `image_view` присутствуют в одном JSON независимо от текущего класса, поэтому
случайное переключение класса не удаляет предыдущую геометрию. Параметры
изображения сверяются при чтении. Если существующий JSON повреждён или не
совпадает по размерности с DICOM, сохранение блокируется вместо сброса разметки.

### Экспорт для обучения моделей

```powershell
docker exec dxa_dicom_labeler python /app/export_geometry.py --output-root /output
```

Создаёт `Размеченные/annotations_geometry.jsonl` и
`Размеченные/annotations_geometry_summary.csv`. JSONL содержит анатомические
точки, линии, прежний полигон, новые свободные штрихи и рамки; CSV — классы, порог яркости, метаданные разметки, количество
объектов и флаги завершения. Отдельный JSONL удобен для дальнейшего обучения
keypoint- и сегментационных моделей.

### Проверка кода без медицинских данных

```bash
python -m pytest -q tests
```

В модульных тестах не используются DICOM; тесты проверяют формат геометрии,
сохранение, экспорт и недопустимые координаты. Сам интерфейс редактора отдельно
проверен в браузере на синтетическом изображении. Для повторного браузерного smoke-теста выполните `python tests/browser_smoke.py`
(локально необходимы Playwright и Chromium). Полный запуск Docker требует
настроенных путей к DICOM на вашей машине.

## Исходные возможности приложения (сохранены)

Streamlit-приложение для ручной разметки DXA/DICOM-изображений.

Приложение запускается через Docker и работает с исходными DICOM в режиме read-only.

## Возможности

Для каждого DICOM можно задать основной класс:

- `LEG` — проксимальный отдел бедра;
- `SPINE` — позвоночник;
- `UNKNOWN` — класс не определён.

Для изображений бедра дополнительно размечаются:

- сторона: `LEFT` / `RIGHT`;
- металл / имплант;
- перелом.

Для позвоночника дополнительно размечается состояние:

- нет выявленной проблемы;
- сколиоз;
- люмбализация;
- сколиоз + люмбализация.

Также можно указать:

- имя разметчика;
- свободный комментарий.

Разметка сохраняется в `labels.csv` и в private DICOM metadata размеченной копии.

Исходные DICOM не изменяются.

## Настройка

Перейдите в папку приложения:

```powershell
cd labeler
```

Создайте `.env`:

```powershell
Copy-Item .env.example .env
```

Стандартная конфигурация:

```env
DXA_DATA_DIR=../Исследования
DXA_OUTPUT_DIR=../Размеченные
DXA_REFERENCE_XLSX=../разметка.xlsx

EXPECTED_DICOM_COUNT=499
EXPECTED_DATASET_FINGERPRINT=
STRICT_DATASET_CHECK=1
```

`.env` является локальным файлом и не должен добавляться в Git.

## Выходные данные

Разметка сохраняется в:

```text
Размеченные/labels.csv
```

Основные колонки:

| Колонка | Значения |
|---|---|
| `relative_path` | относительный путь DICOM |
| `label` | `LEG`, `SPINE`, `UNKNOWN` |
| `side` | `LEFT`, `RIGHT`, пусто |
| `metal` | `0`, `1`, пусто |
| `fracture` | `0`, `1`, пусто |
| `spine_issue` | `NONE`, `SCOLIOSIS`, `LUMBARIZATION`, `BOTH`, пусто |
| `notes` | комментарий |
| `annotator` | разметчик |
| `annotated_at` | дата и время |
| `output_path` | путь размеченной копии |

Для каждого размеченного файла создаётся DICOM-копия с той же относительной структурой каталогов.

## Информация из `разметка.xlsx`

Для текущего `study` приложение дополнительно показывает экспертную информацию из Excel.

В зависимости от выбранной области отображается информация для:

- позвоночника;
- правого бедра;
- левого бедра.

Показываются только признаки со значением `1`.

Значения `0` и пустые ячейки скрываются.

Итог для выбранной области и текстовый комментарий показываются отдельно.

## Навигация

Интерфейс поддерживает:

- выбор DICOM из списка;
- переход к предыдущему и следующему изображению;
- сохранение текущей разметки;
- сохранение и автоматический переход к следующему DICOM;
- отображение прогресса разметки.

Список DICOM и preview кэшируются для уменьшения задержек при навигации.

## DICOM warnings

Некоторые исходные DICOM могут содержать нестандартные значения отдельных metadata-тегов, например длинные `LO` или формально некорректные `UI`.

Приложение не исправляет исходные медицинские metadata.

Такие предупреждения сами по себе не означают повреждение pixel data.

## Пересборка после изменения `app.py`

После изменения исходного кода необходимо пересобрать Docker image:

```powershell
docker compose down
docker compose build --no-cache
docker compose up -d --force-recreate
```

Проверить, какая версия кода находится внутри контейнера:

```powershell
docker exec dxa_dicom_labeler python -c "from pathlib import Path; print(Path('/app/app.py').read_text()[:300])"
```
